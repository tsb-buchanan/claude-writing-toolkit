# Development test results: toolkit 0.1

Runs made while building, before the release test. Each line gives the skill, the place, the sample, the result and notes.
The release test for 0.1 repeats every run, on the web and in Claude Code.

## How the Claude Code runs were made

1. A scratch git repo per sample, with the skill copied into .claude/skills/.
2. A fresh Claude Code session on Sonnet in print mode (`claude -p`), resumed once per reply (`--resume`). The tester answered as the writer, using the sample's doc-profile.md.
3. Allowed tools: Skill, Read, Glob, Grep, Write, Edit, and Bash for git and ls. From human-write on, also Bash for python3, cp, rm and mkdir. Other commands were refused. A real session asks the writer instead.
4. Inside a Claude Code cloud session, the nested session must not inherit the parent's session variables (such as CLAUDE_CODE_SESSION_ID). Otherwise it reuses the parent's session ID.

Problems found, and fixed in the skill, the shared files or the scripts:

1. It deleted a wrong handoff together with the recap before it. Rule 7 now keeps a closing line, even a wrong one, and rule 10 flags it.
2. Without a map, it renamed "totes" to "crates". Rule 9 now says to leave a thing with two names and flag it.
3. A split left a display equation with no words leading into it. In another run it changed the comma inside an equation. Rule 3 now says that nothing inside an equation changes, and that the words around it must fit it.
4. It missed N standing for two things in two of four runs. A check step now asks, for LaTeX, what each symbol stands for.
5. Twice it said it had deleted a file when the command had not run. text-output.md and word-output.md now say to delete with rm as a command on its own, and to report a file as written or deleted only after the command worked.
6. It left check files in the repo. All scratch files now go in drafts/ in the notes folder.
7. check_protected.py crashed on a Word file. It now reads Word files, with all tracked changes accepted. A unit test covers it (32 tests pass).
8. With a Word file in Claude Code, it repeated the new text in the chat. word-output.md now says not to.
9. In the thesis voice "I", it flagged "We propose" instead of fixing it. Rule 8 now says to write "my supervisor and I" for shared work.
10. A widened recap rule made it cut a repeated paragraph, which is doc-flow's call. The rule now defines a recap as a sentence that sums up what the reader has just read.
11. The Claude Code steps for text files moved to shared/text-output.md, which doc-flow and notation-check will also use.
