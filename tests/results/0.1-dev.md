# Development test results: toolkit 0.1

Runs made while building, before the release test. Each line gives the skill, the place, the sample, the result and notes.
The release test for 0.1 repeats every run, on the web and in Claude Code.

## How the Claude Code runs were made

1. A scratch git repo per sample, with the skill copied into .claude/skills/.
2. A fresh Claude Code session on Sonnet in print mode (`claude -p`), resumed once per reply (`--resume`). The tester answered as the writer, using the sample's doc-profile.md.
3. Allowed tools: Skill, Read, Glob, Grep, Write, Edit, and Bash for git and ls only.
4. Inside a Claude Code cloud session, the nested session must not inherit the parent's session variables (such as CLAUDE_CODE_SESSION_ID). Otherwise it reuses the parent's session ID.

Problems found, and fixed in the skill or the samples after these runs:

1. It wrote doc-profile.md as a draft before approval. The skill now says, near the top, to write no file before approval.
2. It used em dashes in its chat messages. The skill now says so near the top, and names what to use instead. The profiles had none. After the change, one run showed none.
3. It pointed out problems in the document during setup. The skill now says to propose settings only.
4. It read a keep light mark on one section as a whole chapter based on a paper. The template and the profile reference now say that paper and passes are for a whole chapter only.
5. With the default keep list accepted, it listed only the marked clause and dropped the default categories. The skill now keeps the defaults. Not yet retested.
6. A comment in the sample chapter said that it had planted problems, and the session repeated the word "planted". The samples no longer say that they are test documents.
