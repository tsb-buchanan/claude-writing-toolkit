# Release test: toolkit 1.0

Every skill was tested on the samples in samples/, on claude.ai and in Claude Code, as CLAUDE.md asks before a release. The runs, with their notes and costs, are in 0.1-dev.md.

## Claude Code

Run by Claude on 28 September 2026, on Sonnet, and on Opus for doc-check full mode. The skills came from the release zip.

| Skill | Result |
|---|---|
| doc-setup | pass on both samples, and on a rerun that changes one rule |
| human-write | pass on both samples, in Word, Markdown and LaTeX, with and without a map |
| doc-flow | pass on both samples, in Word, Markdown and LaTeX, and in "map only" |
| doc-check quick | pass on the report in every run; pass on the thesis in 4 of 6 runs |
| doc-check full | pass on both samples, twice each: as they are, and after two fixes by hand |
| notation-check | pass on the thesis, fixes included; it stops in report mode |

## claude.ai

Run by the writer on 28 September 2026, on Sonnet, with the ten tests in tests/web-test.md. The first doc-flow run ended without a map. After two fixes to doc-flow, the writer reran all ten tests and reported that all of them work.

## Open points

1. Some chat replies on Sonnet still hold an em dash. No file that a skill wrote had one.
2. doc-flow reports on the report sample often run past the 600-word lean cap.
3. doc-check quick on the thesis sometimes leaves out the voice slips or "2 desks".
4. human-write does not flag a result in a method section, and notation-check misses $W$ used before its definition. doc-flow and full mode find these.
5. doc-check full mode has not yet run on a long thesis, so its cost there is an estimate.
